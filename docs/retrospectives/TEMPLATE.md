# 새 회고 항목 작성 양식

기존 주제 문서에 아래 항목을 추가합니다. 같은 문제의 재발·후속 검증은 기존 항목의
진행 기록에 덧붙여 의사결정 이력을 보존합니다. 파일이 길어지면 주제별 문서를
분리하고 [목차](README.md)에 연결합니다.

## RET-주제-번호 — 문제를 드러내는 제목

- **일자:** YYYY-MM-DD (KST), 과거 일자 미상인 경우 명시
- **상태:** 해결 / 완화·우회 운영 / 진행 중 / 확인 필요 / 운영 제외·보류
- **근거:** 사용자 기록 / 코드 확인 / 테스트 / 원본 대조 / 운영 로그 등

**배경·영향:** 무엇을 하던 중 어떤 문제가 생겼고 사용·데이터·운영에 어떤 영향이 있었나?

**관찰과 원인:** 실제 증상·오류와 확인한 사실은 무엇인가? 아직 추정인 원인은 무엇인가?

**시도와 선택 이유:** 무엇을 시도했고 왜 채택·철회했나? 실패한 시도도 남긴다.

**조치와 검증:** 어떤 파일·설계를 바꿨나? 실제로 실행한 테스트·관측 결과는 무엇인가?
로컬 검증과 배포·운영 확인을 구분한다.

**남은 한계·다음 확인:** 해결하지 못한 것, 재발 가능성, 재확인 조건을 적는다.

**관련 근거:** 저장소 내 상대 링크, 확인된 커밋·공개 자료 링크. 비밀값이나 덤프는 넣지 않는다.

**후속 기록:** YYYY-MM-DD — 상태 변경 이유와 새 검증 결과. 미실행 작업은 계획으로 표시.
