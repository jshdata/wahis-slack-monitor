## RET-DASH-01 — 과거 축종 수집이 불완전한 상태에서 보고서별 시각화 제공

- **일자:** 2026-10-29 (KST)
- **상태:** 진행 중 (로컬 구현·검증 완료, 배포·운영 확인 전)
- **근거:** 사용자 요청, 저장소 스키마·알림 코드 확인, 모의 DB 단위 테스트와 Streamlit AppTest

**배경·영향:** Slack 신규 보고서마다 지도를 열고 기간별 발생 흐름을 확인하려 한다.
과거 축종·사육·야생 수집은 미완료여서 이를 필터로 사용하면 실제 발생 추이를 왜곡할 수 있다.

**관찰과 원인:** outbreaks에 좌표·발생일·최초 등록 보고서·최신 갱신 보고서가 있다.
보고서별 모든 과거 갱신 지점 이력은 없어 예전 보고의 전체 지도를 복원할 수 없다.
알림의 신규 건수와 축종 정보는 각각 최초 등록 ID, 해당 보고로 갱신된 발생지라는 서로 다른 범위를 쓴다.

**시도와 선택 이유:** 기존 HTML 통계 대시보드를 유지하고 별도 Streamlit 앱을 추가했다.
축종별 과거 비교는 보류하고 국가·질병별 고유 발생 ID를 집계한다.
지도에 신규와 현재 확인 가능한 기존 갱신 지점을 구분하고 과거 스냅샷이 아님을 안내한다.

**조치와 검증:** 보고서별 조회 모듈, 지도·30/90/365일 막대그래프·상세 목록,
HTTPS 대시보드 URL이 설정된 경우에만 추가되는 Slack 버튼과 실행 안내를 구현했다.
`python -m unittest tests.test_report_dashboard tests.test_report_alert_details tests.test_dashboard`
19개 통과. 모의 데이터로 좌표 누락·미수집·잘못된 진입, 중복 방지 EXISTS 쿼리,
링크 Report ID 전달을 검증했다. 첫 AppTest는 초기 라이브러리 로딩이 기본 3초 제한을
넘어 실패했고 테스트 제한을 15초로 조정한 후 통과했다. 라이브러리 사용 중 폐기 예정 경고가 출력됐다.

**남은 한계·다음 확인:** 실제 DB 조회·브라우저 지도 타일 렌더·외부 배포·Slack 실발송은
수행하지 않았다. 앱 자체 로그인은 없으므로 배포 접근 범위를 결정해야 한다.
Streamlit 서비스 배포와 알림 프로세스의 STREAMLIT_DASHBOARD_URL 설정이 필요하다.
수동 재조회 방식이며 자동 주기 갱신은 미구현이다. 과거 지점 이력·미수집 발생·발생일 누락,
동일 좌표 중첩 한계가 있다. 기존 메시지에는 버튼이 소급 추가되지 않는다.

**관련 근거:** [앱](../../streamlit_app.py), [조회](../../database/report_dashboard_db.py),

### 2026-10-29 (KST) 후속 — Render 배포 준비와 Actions 알림 설정 분리

- **상태:** 진행 중 (배포 구성 준비, Render 계정 연결 대기)
- **확인:** 신규 보고서 알림은 Render 조회 봇이 아니라 GitHub Actions의 WAHIS Monitor에서
  발송한다. Render 봇 환경변수만 바꾸면 새 대시보드 버튼이 생기지 않는다.
  현재 세션에는 Render 인증·CLI·배포 도구 연결이 없고 Windows 자동화용 node_repl도
  제공되지 않는다. 연결 가능한 Render 플러그인을 검색해 사용자에게 연결을 제안했다.
- **조치·이유:** 기존 봇과 충돌하지 않는 별도 무료 서비스 `wahis-report-dashboard`를
  정의한 [render.yaml](../../render.yaml)을 추가했다. DB 환경변수는 sync:false로 두어
  비밀값을 저장소에 쓰지 않는다. 설치 의존성을 대시보드에 필요한 패키지로 분리했다.
  Actions의 `vars.STREAMLIT_DASHBOARD_URL`을 전달하도록 바꿔 전체 환경 Secret 교체 없이
  배포 주소만 설정할 수 있도록 했다. URL 미설정 시 기존 알림만 발송한다.
- **검증:** 관련 테스트 19개 통과. 실제 Render 서비스 생성·공개 health·보고서 URL 확인과
  GitHub Variable 설정은 아직 수행하지 않았다. 이번 변경만 선별하여 GitHub 반영을 진행한다.
- **남은 조건:** Render 연결 후 서비스 생성·DB 설정·배포 성공·주소 확보가 필요하다.
  확정 주소 전에는 로컬 환경이나 Actions에 임의 URL을 설정하지 않는다. 사용자 계정의
  무료 서비스 가용량과 실제 배포 결과는 확인 전이며 유료 전환은 진행하지 않는다.

#### 배포 반영 시도 결과

- 대시보드·배포 설정·관련 회고 12개 파일만 선별해 로컬 커밋 `902c2cd`를 생성했다.
  다른 작업의 회고·AGENTS·gitignore·데이터·백업은 포함하지 않았다.
- `git push origin main`은 실행 전에 자동 승인 검토에서 거절됐다. 사용자의 배포 동의와
  별개로 구체적인 GitHub 저장소·기본 브랜치에 대한 커밋 외부 전송 승인이 명시되지 않았고
  원격 신뢰 확인이 부족하다는 이유였다. 우회 푸시나 다른 API를 통한 전송은 하지 않았다.
- 현재 상태는 로컬 커밋 완료·원격 반영 전이다. 사용자에게 대상 저장소와 커밋을 명시해
  푸시 승인을 요청한다. Render 플러그인도 아직 연결되지 않아 실제 서비스는 생성하지 않았다.
  이 결과 기록은 해당 기능 커밋 이후의 로컬 회고 갱신이며 아직 커밋하지 않았다.
